# GROMACS 2026.4 + NEP/qNEP + WPE 程序介绍、安装与使用

本文档介绍当前最新版本的程序：**GROMACS 2026.4 + 最新 GPUMD NEP/qNEP + Wisevolve
Potential Engine (WPE) 1.0.0**。内容覆盖程序功能、架构、安装、配置、使用方法、验证结果、
性能、限制与故障排查。英文版见
`docs/Program-Introduction-Installation-Usage-EN.md`。

---

## 1. 程序概述

这是一个以 **GROMACS 2026.4** 为宿主、集成 **GPUMD 最新 master 的 NEP/qNEP 势**
和 **WPE 1.0.0** 高性能推理引擎的分子动力学程序。它保留 GROMACS 的积分器、恒温恒压、
约束、键合项、LJ、GPU PME、轨迹/能量输出等全部原有能力，同时把 NEP/qNEP 作为
GROMACS 的力提供者接入。

核心特点：

- **两种 NEP 引擎**：GPUMD 自带 CUDA 核（开源、可替换）与 WPE（闭源高性能引擎，
  运行时 `dlopen`，不参与链接）。
- **三条静电路径**：qNEP 原生 PPPM/Ewald、qNEP + GROMACS GPU PME（链式力）、
  普通 NEP + 经典 MM。
- **NEP-MM 混合体系**：NEP 区与经典 MM 区可在同一 GROMACS 运行中耦合。
- **grompp 不需要 GPU**：可在纯 CPU 机器生成 tpr，再拷贝到 GPU 服务器计算。
- **GPUMD 源码零修改**：`src/external/gpumd` 与上游 GPUMD master 完全一致，
  便于后续替换。

## 2. 主要功能

| 功能 | 支持情况 | 说明 |
|---|---|---|
| 普通 NEP4（`nep4` / `nep4_zbl`，旧格式与新格式） | ✅ | GPUMD 后端与 WPE 后端均支持 |
| qNEP charge1/2/3（`nep4_charge*`、qnep1/2/3） | ✅ | GPUMD 原生 PPPM/Ewald；WPE 用自身 PPPM/Ewald |
| qNEP + GROMACS 自有静电（GPU PME + 链式力） | ✅ | `nnpot-gromacs-charges = yes`，仅 GPUMD 后端 |
| NEP-MM（NEP 区 + 经典 MM） | ✅ | device/host 两条路径均已对照 |
| WPE 1.0.0 后端 | ✅ | 私有二进制，运行时加载，不参与链接 |
| vdW-NEP（`nep_vdw` / `qnep3_vdw`） | ✅ GPUMD / ❌ WPE | WPE 1.0.0 未实现 vdW 家族 |
| D3 色散修正（`nnpot-dftd3`） | ✅ | 在模型与后端都支持时生效 |
| 普通 NEP + GROMACS PME / LJ / 键合项 | ✅ | 原有 GROMACS 路径不变 |
| grompp 免 GPU | ✅ | 纯 CPU 解析模型、选择后端、生成 tpr |
| 设备端事件排序（异步） | ✅ | 默认开启；`GMX_NEP_NO_ASYNC=1` 可回退 |
| NEP5 | ❌ | 最新 GPUMD 的 MD 势类已移除 NEP5；grompp 明确报错 |
| 温度相关 NEP4 | ❌ | 适配层未驱动温度相关力 |
| `nep_dipole` / `polarizability` / `spin` | ❌ | 非普通能量/力模型；grompp 明确报错 |
| 多 GPU / domain decomposition | ❌ | 当前 NEP/WPE 设备路径要求单 rank |

## 3. 架构与数据流

```text
GROMACS MD step
   │
   ├─ 坐标/盒子/类型（device 或 host）
   ▼
src/gromacs/applied_forces/nnpot/
   ├─ NepModel           统一适配层（模型解析、后端选择、缓冲区）
   ├─ nepbackendsettings  auto / gpumd / wpe
   ├─ wpeloader           dlopen + ABI 校验（仅 mdrun 首次求值时）
   ├─ wpepotential        WPE 的 ::Potential 适配
   └─ nepmodel_qnep_gromacs   qNEP-GROMACS 链式力
   │
   ├─ GPUMD 后端：Potential / NEP / NEP_Charge（vendored CUDA 核）
   └─ WPE 后端：libwisevolve_potential.so（C ABI，私有）
   ▼
GROMACS 力归约 / 积分器 / 输出
```

关键设计：

- **WPE 不参与链接**：源码树只包含公开 BSD-2 头文件；`gmx` 用 `dlopen()` 加载
  私有引擎，`ldd gmx` 不会出现 `libwisevolve_potential.so`。
- **grompp 与 mdrun 分离**：grompp 只做 CPU 端模型解析/校验与后端选择，不初始化
  CUDA、不打开 `/dev/nvidia*`、不 `dlopen` WPE；WPE 在 mdrun 首次求值时加载。
- **qNEP-GROMACS 链式力**：qNEP 预测电荷 → 写入 GROMACS 电荷缓冲 → GROMACS
  非键 + GPU PME 计算库仑/倒空间势 → 链式力 `(dE/dq)(dq/dR)` 加回 NEP 力。
- **异步执行**：NEP/WPE 的 kernel 与 GROMACS 的力归约通过设备端事件排序，
  非能量步不需要每步 host 同步。

## 4. 系统要求

| 项 | 要求 |
|---|---|
| 操作系统 | Linux（x86-64） |
| 编译器 | GCC 15.x（或兼容版本） |
| CMake | ≥ 3.28 |
| CUDA | CUDA Toolkit 13.x（实测 13.4，nvcc 13.4.92） |
| GPU | NVIDIA，sm_80 及以上（实测 RTX 4090 D / sm_89，24 GB） |
| CPU | 支持 AVX2（默认 `GMX_SIMD=AVX2_256`） |
| FFT | 系统 FFTW3 |
| MPI | 不需要；使用 GROMACS thread-MPI |
| WPE 运行库 | 可选；WPE 1.0.0 为私有 `.so`，基于 CUDA 12，需要 `libcufft.so.11` |

> WPE 运行库不随源码包分发。只使用普通 NEP/qNEP（GPUMD 后端）时不需要 WPE。

## 5. 安装

### 5.1 解压

```bash
tar -xzf gromacs-2026.4-nep-source-20261104.tar.gz
cd gromacs-2026.4-nep
```

### 5.2 一键构建（推荐）

```bash
# 默认：Release + -march=native + WPE 后端开启 + 自动检测 CUDA 架构 + 单元测试
./build-nep.sh

# RTX 4090（sm_89）
CUDA_ARCH=89 ./build-nep.sh

# RTX 5090（sm_120）
CUDA_ARCH=120 ./build-nep.sh

# 不编译 WPE 后端
WPE=0 CUDA_ARCH=89 ./build-nep.sh

# 编译并安装到 install-nep/
DO_INSTALL=1 CUDA_ARCH=89 ./build-nep.sh

# 指定 WPE 库路径提示（仅配置期提示，运行期仍按搜索路径加载）
WPE_LIBRARY=/path/to/wpe.so/lib CUDA_ARCH=89 ./build-nep.sh

# 可选：LTO、清理重建
LTO=1 CUDA_ARCH=89 ./build-nep.sh
CLEAN_BUILD=1 CUDA_ARCH=89 ./build-nep.sh
```

产物：

- `build-nep/bin/gmx`
- `install-nep/`（仅 `DO_INSTALL=1`）

`build-nep.sh` 支持的环境变量：

| 变量 | 默认 | 含义 |
|---|---|---|
| `BUILD_DIR` | `build-nep` | 构建目录 |
| `INSTALL_PREFIX` | `install-nep` | 安装前缀 |
| `BUILD_JOBS` | `nproc` | 并行任务数 |
| `BUILD_TYPE` | `Release` | CMake 构建类型 |
| `CUDA_ARCH` | 自动检测 | 如 `89`、`120` |
| `NATIVE_CPU` | `1` | `-march=native -mtune=native` |
| `FAST_MATH` | `0` | 额外 `--use_fast_math`（GROMACS CUDA 构建默认已启用） |
| `LTO` | `0` | 过程间优化 |
| `WPE` | `1` | 是否编译 WPE 后端 |
| `WPE_LIBRARY` | 空 | 配置期 WPE 路径提示 |
| `RUN_TESTS` | `1` | 构建后运行 NNPot 单元测试 |
| `CLEAN_BUILD` | `0` | 先删除构建目录 |
| `DO_INSTALL` | `0` | 执行 `cmake --install` |

### 5.3 手动 CMake（等价）

```bash
cmake -S . -B build-nep \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_CUDA_ARCHITECTURES=89 \
  -DCMAKE_C_FLAGS_RELEASE="-O3 -DNDEBUG -march=native -mtune=native" \
  -DCMAKE_CXX_FLAGS_RELEASE="-O3 -DNDEBUG -march=native -mtune=native" \
  -DCMAKE_CUDA_FLAGS_RELEASE="-O3 -Xptxas -O3 --extra-device-vectorization" \
  -DGMX_GPU=CUDA \
  -DGMX_NNPOT=NEP \
  -DGMX_NEP_WPE=ON \
  -DGMX_MPI=OFF \
  -DGMX_THREAD_MPI=ON \
  -DGMX_OPENMP=ON \
  -DGMX_FFT_LIBRARY=FFTW3 \
  -DGMX_SIMD=AVX2_256 \
  -DBUILD_TESTING=ON \
  -DGMX_BUILD_UNITTESTS=ON \
  -DREGRESSIONTEST_DOWNLOAD=OFF

cmake --build build-nep --parallel "$(nproc)"
```

如不需要 WPE，把 `-DGMX_NEP_WPE=ON` 改为 `OFF`。

### 5.4 WPE 运行库配置

WPE 是私有运行库，需要单独获得并让 `gmx` 能找到它。两种方式任选：

```bash
# 方式一：环境变量
export LD_LIBRARY_PATH=/path/to/cuda12-cufft/nvidia/cufft/lib:$LD_LIBRARY_PATH
export GMX_WPE_LIBRARY=/path/to/wpe.so/lib
```

```text
# 方式二：mdp
nnpot-wpe-library = /path/to/wpe.so/lib
```

`nnpot-wpe-library` 可以是 `.so` 文件，也可以是包含
`libwisevolve_potential.so` 的目录。加载失败时优先检查：

1. `libwisevolve_potential.so` 是否存在；
2. 是否缺少 `libcufft.so.11`（WPE 1.0.0 基于 CUDA 12）；
3. ABI 版本是否与头文件 `src/external/wpe/wisevolve_potential_api.h` 匹配。

### 5.5 安装后自检

```bash
export PATH=$PWD/build-nep/bin:$PATH

gmx --version | grep -E 'CUDA|SIMD'

# 单元测试（模型解析 / WPE 形状检查）
ctest --test-dir build-nep -R NNPotAppliedForcesUnitTest --output-on-failure

# CPU 端到端（16 项，无需 GPU）
GMX=$PWD/build-nep/bin/gmx WPE_LIB=/path/to/wpe.so/lib \
  test/2026.4-validation/run_cpu_validation.sh
```

## 6. 快速开始

以下示例均假设已 `gmx grompp` 生成 tpr。

### 6.1 普通 NEP（GPUMD 后端）

`run.mdp`：

```text
integrator      = md
dt              = 0.0005
nsteps          = 2000
nstenergy       = 100
nstlog          = 1000

nnpot-active    = yes
nnpot-modelfile = nep.txt
nnpot-backend   = gpumd
```

```bash
gmx grompp -f run.mdp -c conf.gro -p topol.top -o run.tpr
gmx mdrun -s run.tpr -ntmpi 1 -ntomp 1
```

### 6.2 qNEP 原生静电（GPUMD 或 WPE）

```text
nnpot-active          = yes
nnpot-modelfile       = qnep_model1.txt
nnpot-backend         = gpumd          ; 或 wpe
nnpot-gromacs-charges = no
nnpot-gpumd-kspace    = pppm           ; 或 ewald（GPUMD 后端）
nnpot-wpe-kspace      = pppm           ; 或 ewald（WPE 后端）
```

### 6.3 qNEP + GROMACS 自有静电（仅 GPUMD 后端）

```text
nnpot-active           = yes
nnpot-modelfile        = qnep_model1.txt
nnpot-backend          = gpumd
nnpot-gromacs-charges  = yes

coulombtype            = PME
rcoulomb               = 0.8
rlist                  = 0.8
pme-order              = 4
```

要求：

- 单 rank、full-system（不支持 DD）；
- `pme-order = 4`，`rcoulomb = rlist`；
- 盒长 ≥ 2.5 × `rcoulomb`；
- 不支持 ZBL、charge3、FEP、MTS。

### 6.4 WPE 后端

```bash
export LD_LIBRARY_PATH=/path/to/cuda12-cufft/nvidia/cufft/lib:$LD_LIBRARY_PATH
export GMX_WPE_LIBRARY=/path/to/wpe.so/lib
```

```text
nnpot-active           = yes
nnpot-modelfile        = qnep_model1.txt
nnpot-backend          = wpe
nnpot-wpe-kspace       = pppm           ; 或 ewald
nnpot-wpe-pppm-spacing = 1.0            ; Å
```

```bash
gmx grompp -f run.mdp -c conf.gro -p topol.top -o wpe.tpr
gmx mdrun -s wpe.tpr -ntmpi 1 -ntomp 1
```

### 6.5 NEP-MM

示例目录：`examples/nep-mm-methane-water/`，包含 `nep-mm.mdp`、拓扑与运行脚本。

### 6.6 在 CPU 上生成 tpr，在 GPU 上计算

```bash
CUDA_VISIBLE_DEVICES="" gmx grompp -f run.mdp -c conf.gro -p topol.top -o cpu.tpr
# 不访问 /dev/nvidia*，不 dlopen WPE；tpr 可拷贝到 GPU 机器直接 mdrun
```

## 7. `.mdp` 选项参考

### 7.1 新增选项

| 选项 | 默认 | 取值/说明 |
|---|---|---|
| `nnpot-backend` | `auto` | `auto` / `gpumd` / `wpe` |
| `nnpot-wpe-library` | 空 | WPE 库文件或目录；不填则查 `GMX_WPE_LIBRARY`、`LD_LIBRARY_PATH` |
| `nnpot-wpe-kspace` | `pppm` | `pppm` / `ewald` |
| `nnpot-wpe-pppm-spacing` | `1.0` | Å，0.2–2.0 |
| `nnpot-gpumd-kspace` | `pppm` | `pppm` / `ewald`（GPUMD 原生 qNEP） |
| `nnpot-gpumd-pppm-spacing` | `0` | Å，0 表示用模型默认 |
| `nnpot-dftd3` | 空 | 如 `"pbe 12.0 12.0"`；模型与后端都支持时生效 |

### 7.2 后端选择逻辑

- `nnpot-backend = gpumd`：强制 GPUMD 后端；模型不支持时报错。
- `nnpot-backend = wpe`：强制 WPE；未编译 WPE、库找不到或模型形状不满足时报错。
- `nnpot-backend = auto`（默认）：若编译了 WPE、模型满足 WPE 形状约束、且能找到运行库，
  选 WPE；否则选 GPUMD，并在 `md.log`/grompp 输出中说明原因。

WPE 形状约束（grompp 阶段静态检查）：

- `l_max_3body = 4`；
- ANN 隐藏层宽度 ≤ 256。

### 7.3 运行时环境变量

| 变量 | 作用 |
|---|---|
| `GMX_WPE_LIBRARY` | WPE 库搜索路径 |
| `GMX_NEP_NO_ASYNC=1` | 回退到“每步 host 同步”路径（对比/排障） |
| `GMX_WPE_ATOM_VIRIAL=1` | 让 WPE 请求逐原子 virial（调试；默认系统 virial 更快） |
| `GMX_QNEP_DEBUG` | 输出 qNEP 适配层调试信息 |
| `GMX_CUDA_GRAPH` | 尝试 GROMACS 的 MD GPU Graph（外部 WPE 路径可能不兼容，需实测） |

## 8. 模型支持

| 模型 | GPUMD 后端 | WPE 后端 | 备注 |
|---|---|---|---|
| `nep4` / `nep4_zbl`（旧格式） | ✅ | ✅ | 旧格式首行标签 |
| `nep <N> ...`（新格式） | ✅ | ✅ | 自动转换为 MD 输入 |
| `nep4_charge1/2/3`、`_zbl_` | ✅ 原生 | ✅ qNEP | WPE 用自身 PPPM/Ewald |
| qnep1/2/3（新格式） | ✅ | ✅ | |
| `nep_vdw` / `qnep3_vdw` | ✅ | ❌ | WPE 1.0.0 未实现 vdW 家族 |
| `nep5` / `nep5_zbl` | ❌ | ❌ | 最新 GPUMD 已从 MD 势类移除 |
| 温度相关 NEP4 | ❌ | ❌ | 适配层未驱动 |
| `nep_dipole` / `polarizability` / `spin` | ❌ | ❌ | 非普通能量/力模型 |

## 9. 运行与输出

### 9.1 运行

```bash
gmx mdrun -s run.tpr -ntmpi 1 -ntomp 1
```

- NEP/WPE 设备路径要求 **单 rank**（`-ntmpi 1`），不要使用 DD；
- `-ntomp 1` 即可；多线程对 GPU 路径帮助很小；
- WPE 只使用一个可见 GPU。

### 9.2 输出

- `md.log`：模型信息、后端选择、性能（`Performance:` 行）；
- `ener.edr`：能量、温度、压力等；用 `gmx energy` 选择 `NN-Potential`
  （或启用 GROMACS 静电时的 `Potential`）；
- `traj_comp.xtc`、`confout.gro`、`mdout.mdp` 等 GROMACS 标准输出。

`Performance:` 行的四列依次是：

```text
Performance:  <ns/day>  <hour/ns>  <ms/step>  <Matom·steps/s>
```

注意 `ms/step` 是第 4 列。

## 10. 正确性与性能摘要

> 测试环境：RTX 4090 D（sm_89，24 GB），驱动 595.99.02，CUDA 13.4；GROMACS
> 2026.4 mixed/thread-MPI/CUDA/AVX2；GPUMD 与 WPE 使用同一份源码/运行库。
> 详细数据见 `docs/GPU-TESTS-2026.4.md`。

### 10.1 单点精度（vs GPUMD 本体）

| 路径 | ΔE (eV/atom) | 力 RMS (eV/Å) |
|---|---|---|
| 普通 NEP（CH4） | 1.7e-5 | 5.1e-5（0.004%） |
| qNEP 原生（水） | ~5e-6 | 3.5–3.9e-5（0.0025–0.0028%） |
| qNEP + GROMACS PME（水） | -6.8e-6 | 1.9e-4（0.0135%） |
| WPE PPPM（水 qNEP） | -2.8e-8 | 1.0e-5（0.0007%） |
| WPE Ewald（水 qNEP） | -8.8e-8 | 1.0e-5（0.0007%） |
| WPE（CH4 plain） | -3.2e-8 | 4.5e-5（0.0035%） |

### 10.2 其他验证

- **有限差分**（qNEP-GROMACS，6 原子，±2e-3 nm）：最大相对误差 **0.95%**，通过；
- **NVE 漂移**（水 qNEP，0.5 fs，2 ps，先 NVT）：**-3.1e-6 eV/(atom·ps)**
  （异步路径 -2.8e-6）；
- **NEP-MM**：NEP 能量相同，NEP 区力 RMSE **2.1e-6 kJ/mol/nm**；
- **NPT/NPH**（WPE 200 ps / GPUMD 后端 100 ps）：GROMACS–GPUMD 压力差
  **1.0–7.5 bar（≤0.8σ）**；密度/势能仍有 ~0.5–0.6% / ~1×10⁻³–1.3×10⁻² eV/atom（原生 NPH 最大）的差，
  且 100–200 ps 内仍在漂移，属未收敛的采样差异；
- **自动测试**：单元测试 **1/1**，CPU 端到端 **16/16** 通过。

### 10.3 性能（单 GPU，NVE，0.5 fs）

| 体系 | 引擎 | ms/step | ns/day | 相对 GPUMD 本体 |
|---|---|---|---|---|
| 1500 | GROMACS+WPE（qNEP） | 0.387 | 111.8 | 2.57× |
| 1500 | GPUMD+WPE | 0.362 | 119.3 | 2.75× |
| 1500 | GROMACS+GPUMD 后端（qNEP） | 0.988 | 43.7 | 1.006× |
| 1500 | GPUMD 本体（qNEP PPPM） | 0.994 | 43.5 | 1.00× |
| 1500 | GROMACS PME（qNEP-GROMACS） | 1.191 | 36.3 | 0.83× |
| 1500 | GROMACS+WPE（CH4 plain） | 0.324 | 133.3 | 2.09× |
| 18 000 | GROMACS+WPE | 0.632 | 68.4 | 2.36× |
| 18 000 | GPUMD+WPE | 0.577 | 74.9 | 2.58× |
| 18 000 | GROMACS+GPUMD 后端 | 1.529 | 28.3 | 0.97× |
| 18 000 | GPUMD 本体（qNEP PPPM） | 1.488 | 29.0 | 1.00× |
| 18 000 | GROMACS PME（qNEP-GROMACS） | 2.572 | 16.8 | 0.58× |

要点：

- WPE 相对 GPUMD 原生后端：1500 原子 **2.09×（plain NEP）/ 2.57×（qNEP）**；
  18k 原子 **2.36×（GROMACS）/ 2.58×（GPUMD）**。
- 同引擎对照：GROMACS+WPE 比 GPUMD+WPE 慢 **7%（1500）/ 9.6%（18k）**。
- qNEP-GROMACS（PME）在 18k 时仍慢于引擎内置 PPPM（2.57 vs 1.53 ms/step），
  单 GPU 18k 规模下未出现“PME 反超”。

## 11. 已知限制

1. **NEP/WPE 设备路径要求单 rank、无 DD**：不支持多 GPU/domain decomposition；
   WPE 只使用一个可见 GPU。
2. **WPE 与 GROMACS 自有静电不兼容**：WPE 引擎内部完成 qNEP 静电，无法输出
   GPUMD 的 `D_real` 链式势；该组合 grompp 报错，建议 `nnpot-backend = gpumd`。
3. **qNEP-GROMACS 限制**：单 rank、full-system、`pme-order=4`、`rcoulomb=rlist`、
   盒长 ≥ 2.5·`rcoulomb`；不支持 ZBL/charge3/FEP/MTS。
4. **WPE 运行库依赖**：WPE 1.0.0 基于 CUDA 12，需要 `libcufft.so.11`；CUDA 13
   系统需额外提供 CUDA 12 cuFFT，或使用 Wisevolve 的 CUDA 13 构建。
5. **WPE 不支持 vdW 家族**；WPE 形状约束 `l_max_3body=4`、ANN ≤ 256。
6. **NEP5、温度相关 NEP4、dipole/polarizability/spin 不支持**，grompp 明确报错。
7. **`.qnc` 电荷落盘**：全体系 NEP 下 GROMACS 关闭经典非键/PME，不产生设备坐标
   缓冲，`nnpot-charges-nst` 的二进制电荷输出不触发（tpr 中仍含 `QNC1` 头）。
8. **已验证的最大体系为 18 000 原子**；更大体系、多 GPU、DD 未测试。
9. **性能数字基于 0.5 fs 步长**；使用 HMR/SETTLE 提高 dt 时需重新验证动力学与
   热力学量。

## 12. 故障排查

### 12.1 `mdrun` 报找不到 `libwisevolve_potential.so`

- 检查 `nnpot-wpe-library` / `GMX_WPE_LIBRARY` / `LD_LIBRARY_PATH`；
- 若报缺 `libcufft.so.11`，把 CUDA 12 的 cuFFT 目录加入 `LD_LIBRARY_PATH`；
- grompp 只检查文件存在，不 `dlopen`；加载失败发生在 mdrun 首次求值。

### 12.2 明明有 WPE，为什么选了 GPUMD？

`nnpot-backend = auto` 在以下情况会回退到 GPUMD：

- 编译时 `GMX_NEP_WPE=OFF`；
- 模型不满足 WPE 形状约束（`l_max_3body=4`、ANN ≤ 256）；
- 找不到 WPE 运行库。

grompp/md.log 会打印选择原因。需要强制 WPE 时设 `nnpot-backend = wpe`，让错误显式暴露。

### 12.3 `gmx grompp` 需要 GPU 吗？

不需要。可用：

```bash
CUDA_VISIBLE_DEVICES="" gmx grompp -f run.mdp -c conf.gro -p topol.top -o cpu.tpr
```

生成的 tpr 可拷贝到 GPU 机器直接 `mdrun`。

### 12.4 压力与 GPUMD 差几十 bar？

先看误差棒：50 ps 时压力 SEM 就有 15–24 bar；200 ps 下差 1.0–7.5 bar（≤0.8σ），
在统计误差内。另注意 GPUMD 压力符号为 `+(sxx+syy+szz)/3`。

### 12.5 如何回退异步路径？

```bash
GMX_NEP_NO_ASYNC=1 gmx mdrun -s run.tpr -ntmpi 1 -ntomp 1
```

### 12.6 NEP5 / spin / dipole 模型报错？

这些模型当前不支持；grompp 会给出原因。请改用 NEP4/qNEP 模型。
